# UX参照研究 統合文書 — imutaro.com 本体還元 & lab 立ち上げ用

作成日: 2026-08-05
収集アングル: ①受賞ポートフォリオ ②D2C/飲食EC ③スタジオ・メディア・潮流（計14サイト + 2潮流）

## 0. 前提（imutaro.com 本体の確定制約）

- 本体は **常時動くアニメ禁止**（アイドル時 Paint/Raster 0ms）、**スクロール連動演出禁止**、**mask 禁止**
- 動きが許されるのは **初回入場** と **hover / click** のみ（DESIGN.md「アイドル時とスクロール中は完全静止」と一致）
- 実験場（lab）は制約なし。ただし `prefers-reduced-motion` 尊重と性能計測は文化として持ち込む

タグ定義:

| タグ | 意味 |
|---|---|
| `本体可` | 入力駆動（初回入場 / hover / click）かつ有限で収束。本体に還元できる |
| `本体条件付` | トリガーや実装次第で本体可（例: スクロール到達トリガーなら禁止、初回入場なら可） |
| `lab` | 常時アニメ・スクロール連動・リアルタイムレンダリングを含み、本体禁止。lab で実験する |

## 3. lab 1本目の推薦テーマ 3案

### 案1: View Transitions 遷移カタログ（推し・工数最小）

- **何を作るか**: MPA 構成の小さなページ群で、共有要素モーフ / 方向つきスライド / clip-path ワイプ / レターシャッフル風の遷移を1つずつ実装したデモカタログ。各遷移に「非対応ブラウザでの挙動」「reduced-motion 時の挙動」の注記を付ける
- **どの参照の何を学ぶか**: Piccalilli の実例集（`@view-transition { navigation: auto }` と `view-transition-name`）、Robin Noguier の「クリック画像→次ページヒーロー」の文脈連続、Lallé/Crav の「404 まで統一」思想
- **工数感**: 小（週末1〜2日）。JS フレームワーク不要、CSS 主体
- **選ぶ理由**: 3案中で唯一、成果がそのまま本体還元（下記 Top3 の1位）に直結する。lab 1本目として「作った→本体が良くなった」のループを最短で回せる
- **破綻しうる条件**: Next.js App Router のクライアント遷移と View Transitions の統合はまだ発展途上。lab は素の MPA で作れば回避できるが、本体還元時に Next.js 側の対応状況の確認が必要

### 案2: タイポグラフィ物理遊び場（Matter.js）

- **何を作るか**: 見出し文字がクリック/ホバーで落下・衝突・積み上がる1ページ。物理が静止（sleep）したら rAF ループを完全停止させ、DevTools トレースで「アイドル時 Paint/Raster 0ms」を実証するところまで含める
- **どの参照の何を学ぶか**: Wodniack（**ソースが GitHub で OSS 公開**されており、コピーでなく読解学習ができる）、Locomotive の「遊びを1箇所に集中させる」配分思想、Bruno の配慮 UI
- **工数感**: 中（2〜3週末）。Matter.js 学習＋停止管理の設計が本体
- **選ぶ理由**: 「学習記録サイト」という imutaro.com の性格と最も思想が合う参照（Wodniack）を深掘りできる。物理の停止管理は本体の性能文化とそのまま接続する
- **破綻しうる条件**: 物理演出は「触って面白い」の調整（質量・反発係数）に時間が溶けやすい。タイムボックスを切らないと工数中では済まない

### 案3: スクローリーテリング解放区

- **何を作るか**: 本体で禁止した「スクロール連動」を思い切り実験する1本。CSS ネイティブの Scroll-driven Animations（`animation-timeline: scroll()`）と JS 駆動（IntersectionObserver / GSAP ScrollTrigger）を同じ演出で二重実装し、Paint/Raster トレースで性能比較する
- **どの参照の何を学ぶか**: The Pudding のスクロール同期の物語構成、Robin Noguier の速度連動演出、Exo Ape の段階的リビール
- **工数感**: 中〜大（3週末〜）。演出＋計測レポートの2本立て
- **選ぶ理由**: 「本体禁止事項の解放区」という lab の存在意義を最も体現する。計測比較はそのまま Zenn 記事ネタになる
- **破綻しうる条件**: 比較対象（演出の題材）を決めないと発散する。学習ログのデータ（記事数推移など）を題材に固定するのが現実的

**推薦順**: 案1 → 案2 → 案3。案1で「lab→本体還元」の型を作り、案2で遊びの深さ、案3で禁止領域の探索、と段階を踏むのが低リスク。

## 4. 本体に今すぐ還元できるパターン Top3

### 1位: View Transitions API による一覧→詳細の共有要素モーフ（語彙 #13）

- **参照**: Robin Noguier / Exo Ape / Piccalilli
- **適用箇所**: `(blog)` の記事一覧（`components/ArticleList` / `ArticleListItem`）→ 記事詳細（`components/Article` / `PageHead`）。記事タイトル要素に `view-transition-name` を付与し、一覧の行タイトルが詳細ページの見出しへ連続移動する
- **制約適合**: クリック駆動・有限・CSS のみ。非対応ブラウザは通常遷移に自動フォールバック（プログレッシブエンハンスメント）。`prefers-reduced-motion` でクロスフェードのみに落とす
- **効果**: Exo Ape の言う「方向感覚を生む装置」。一覧⇔詳細の往復が多い学習記録サイトで文脈の途切れをなくす

### 2位: 記事一覧の hover-reveal（行ホバーで情報プレビュー）（語彙 #7・#8）

- **参照**: Mouthwash Studio / Dennis Snellenberg
- **適用箇所**: `ArticleListItem` の行ホバーで、リード文・タグ・日付などのメタ情報（あればアイキャッチ）をフロート表示。Mouthwash 同様「初期状態は文字インデックス、ホバーで初めてビジュアル」の方針は、白×罫線×mono のフィールドノート語彙とトーンが一致する
- **制約適合**: hover 駆動・有限。mask 不使用（opacity + transform + clip-path）。タッチ環境ではホバーなし=情報は詳細ページで見る、で成立
- **効果**: 「装飾は情報を運ぶものだけ」という DESIGN.md の原則のまま一覧を探索空間に変えられる

### 3位: 404・エラーページへの入場演出統一（語彙 #17・#1）

- **参照**: Grégory Lallé / Crav Burgers
- **適用箇所**: `app/not-found.tsx`（`not-found.module.css` が既にある）。LP で確立済みの初回入場語彙（fadeInUp スタッガ、mono のログ風文言 — Crav の「PREPARING...」の 404 版として `ERROR 404: page not found in field notes...` のような一行）を最小適用する
- **制約適合**: 初回入場のみ・有限。既存の LP 演出資産を再利用するだけで新規実装がほぼない
- **効果**: 「入口から出口・エラーまで演出が統一されている」ことが Awwwards 審査でも評価される品質シグナル。最小工数で世界観の完成度が上がる

次点: マグネティックホバー（#6）は定番だが「静けさ」トーンと衝突する懸念があり、採用するならフッターの CTA 1箇所限定（Locomotive の「遊びは1箇所に集中」原則）を推奨。
